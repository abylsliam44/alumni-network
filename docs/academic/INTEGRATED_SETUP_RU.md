# Полная платформа с MongoDB-проектами: локальная демонстрация

В объединённом режиме используется основной интерфейс Alumni Network: пользователи, профили, сообщения, вакансии, мероприятия и менторство остаются в основной платформе. Проектная доска, рекомендации, отклики и события проектов работают с MongoDB. Это локальная интеграция для демонстрации; полная приёмка исходных и новых функций ещё не завершена.

## Как связаны учётные записи

- Вход и исходный профиль остаются в PostgreSQL. MongoDB не проверяет пароль вместо основной платформы: существующая сессия проверяется основным backend.
- При обращении к проектам backend берёт действующего пользователя и публичные данные профиля из PostgreSQL и обновляет его проектное представление в MongoDB по тому же UUID. Хеш пароля не копируется: MongoDB получает нерабочий маркер `!`.
- Навыки для рекомендаций берутся из основного профиля; категории и интересы для проектов настраиваются через **Project preferences** и хранятся в MongoDB. Настройки являются отдельными предпочтениями проектной доски.
- Данные старой SQL-базы и прежней учебной базы `alumni_academic` в объединённую демонстрационную базу автоматически не переносятся. Для использования реальных данных нужна отдельная проверенная миграция.

## Запуск

Нужны Docker Desktop и локальный `.env`. Если файла ещё нет, создайте его из `.env.example`, установите локальные значения и секрет приложения. Если `.env` уже есть, сохраните его; не перезаписывайте.

```bash
docker compose -f docker-compose.yml -f docker-compose.integrated.yml up -d --build
```

Compose создаёт отдельный проект `alumni-full-demo` с отдельными volumes PostgreSQL, MongoDB и других сервисов; существующие volumes прежнего приложения и `alumni-academic` не используются. На старте backend применяет Alembic-миграции к **этой отдельной** PostgreSQL-базе. Не используйте эту конфигурацию для переноса реальных или production-данных. Сервис `agent` в текущем репозитории отсутствует и выключен через необязательный профиль; работоспособность функций, зависящих от него или внешних AI-провайдеров, не подтверждена.

Заполните отдельную базу синтетическими данными:

```bash
docker compose -f docker-compose.yml -f docker-compose.integrated.yml exec -e INTEGRATED_DEMO_SEED=true backend python -m scripts.integrated_demo_seed
```

Seed создаёт 12 демонстрационных пользователей и 24 проекта и не перезаписывает существующие записи с теми же идентификаторами. Он специально ограничен включённым интегрированным режимом и базой MongoDB `alumni_integrated`; используйте его только с отдельной локальной PostgreSQL-базой из Compose выше.

- Полная платформа: http://localhost:3030
- Вход: `demo0@integrated.example.com`, пароль `DemoPass123!` (только синтетическая демонстрационная учётная запись).
- В меню доступны **Projects**, **Project matches**, **Saved projects**, **Project activity** и **Project preferences**, наряду с существующими разделами.
- API и Swagger: http://localhost:8010/docs; готовность MongoDB: http://localhost:8010/api/health/ready.
- MongoDB Compass: `mongodb://127.0.0.1:27019/?directConnection=true`, база `alumni_integrated`.

## Как показать проект на защите

1. Откройте платформу и войдите под `demo0@integrated.example.com`. Покажите боковое меню: здесь вместе находятся существующие разделы платформы и новая проектная доска.
2. В **Profile** откройте редактирование профиля: навыки пользователя в основной системе влияют на подбор проектов. Категории и интересы для подбора задаются отдельно через **Project preferences**.
3. Откройте **Projects**. Здесь можно найти проект, использовать фильтры и перейти в карточку. Проекты читаются из MongoDB.
4. Откройте **Project matches**. Баллы складываются из совпадений навыков, категории и интересов; объяснение показано рядом с рекомендацией. Это баллы модели, а не вероятность успеха. Проекты, на которые пользователь уже откликнулся, исключаются из персональной выдачи.
5. В карточке проекта нажмите сохранение, поставьте оценку и посмотрите **Saved projects** и **Project activity**. Отклик удобнее показывать последним: после него проект исчезает из персональной выдачи. Повторный отклик на тот же проект запрещён.
6. В MongoDB Compass откройте подключение к порту `27019`, базу `alumni_integrated` и коллекции `projects`, `users`, `interactions`, `project_applications`. После действий в интерфейсе обновите коллекцию, чтобы увидеть новые записи. `users` здесь — проектное представление профиля, а основная учётная запись остаётся в PostgreSQL.

При показе обратите внимание: исходные сообщения, вакансии и менторство относятся к основной платформе; их данные не перенесены в MongoDB. Заполненные здесь пользователи и проекты синтетические. Отдельный старый учебный стенд на порту 3031 использует другую базу и другие учётные записи.

Если одновременно открыта прежняя учебная версия на порту 3031, браузер разделяет cookies между портами одного и того же hostname. Чтобы сессии не мешали друг другу, открывайте объединённую версию через `localhost:3030`, а отдельную учебную — через `127.0.0.1:3031`.

Проверка интеграционного сценария в отдельной демонстрационной базе:

```bash
docker compose -f docker-compose.yml -f docker-compose.integrated.yml exec -e INTEGRATED_DEMO_SEED=true backend python -m unittest tests.test_integrated_projects -v
```

Тест создаёт и удаляет свой уникальный тестовый проект и связанные с ним тестовые записи. Он проверяет единый вход, доступ к основным API, создание проекта, сохранение, идемпотентность и отклик в MongoDB. Это не полный набор проверок всей платформы.

Остановка с сохранением данных:

```bash
docker compose -f docker-compose.yml -f docker-compose.integrated.yml down
```

Не добавляйте `-v`: этот флаг удаляет volumes. Прежняя отдельная учебная конфигурация описана в [SETUP.md](SETUP.md).
